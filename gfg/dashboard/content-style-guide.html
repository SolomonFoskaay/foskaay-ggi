✏ Content Style Guide

The rules every AI agent must follow when writing user-facing text. Enforced in .opencode/rules/content-style-guide.md (auto-loaded every session).

1. No em dashes or double dashes in user-facing content

Em dashes (—) and double dashes (--) are the single biggest tell of AI-generated text. Every piece of user-facing copy must avoid them.

Never write this

a big green "pea" — sent back home

play now — it's free

fast and fair — every roll on-chain

Write this instead

a big green "pea" (sent back home)

play now, it's free

fast and fair, every roll on-chain

Instead ofUse
the app — free to play the app (free to play)
sign in — then play sign in and then play
Ludo — the classic board game Ludo, the classic board game
your games — your points — your history your games, your points, and your history
We built this — it works great We built this. It works great.

2. What to use instead

Replace the dash with whichever fits naturally:

  • Parentheses for asides: the app (free to play) works on any phone
  • Commas for lists or pauses: fast, fair, and fully on-chain
  • "and" for connections: sign in and start playing
  • Full stop to split into two sentences: The app is free. Every roll is on-chain.

3. Where this rule applies

  • Changelog summaries (public user-facing text in changelog.json)
  • Page copy (about, support, forum, contact, profile, changelog intros)
  • UI labels and button text
  • Error messages shown to users
  • Forum posts, articles, announcements
  • README descriptions (public-facing ones)
  • Any text a player or visitor reads

4. Where this rule does NOT apply

  • Code comments (internal, never shown to users)
  • Git commit messages
  • Internal developer notes (docs/changelog/, unreleased.md)
  • Variable names, function names, technical identifiers
  • On-chain instruction names or account labels

5. How the agent enforces this

The rule is loaded automatically at the start of every opencode session via opencode.json instructions. Before writing ANY user-facing content, the agent checks this guide. If the content contains an em dash or double dash, it is rewritten using parentheses, commas, "and", or full stops. No exceptions.
